1. BLOCKING - MUST BE DONE BEFORE LAYOUT
================================================================================

1.1 FOOTPRINTS NOT ASSIGNED
    No component on any sheet has a footprint. This is the single biggest
    remaining task. Nothing can be laid out until it is done.

1.2 SECURE CONNECTORS REQUIRED (design doc constraint, currently unmet)
    The radio doc says verbatim: "Do not do simple 2.54mm male/female pin
    headers; it WILL go loose during comp."
    The control board doc says: "Make sure ports are using secure connectors
    (try to find cheaper Molex alternatives)".
      - J14 RADIO_MEZZANINE is currently a generic Conn_02x05. It MUST get a
        latching mezzanine / board-to-board footprint, not a pin header.
      - J5-J9  (motor/dribbler), J10 (kicker), J11/J12 (expansion) must all get
        latching JST/Molex footprints.
    The schematic symbols are generic, so this is purely a footprint + BOM
    decision - but it is a stated requirement, not a preference.

1.3 OLED CONNECTOR PIN ORDER NOT VERIFIED  <-- needs a human with the part
    J13 is wired as:
        1=SDA  2=SCL  3=GND  4=RST  5=GND  6=NC  7=+5V  8=GND
    The intent is that pin 3 (SA0) grounded selects I2C address 0x3C and pin 5
    (CS) grounded enables I2C mode - both standard for an SSD1306 breakout.
    This has NOT been checked against the actual Adafruit #326 silkscreen.
    Verify before layout; a wrong order here is a dead display and a respin.


================================================================================
2. ELECTRICAL FINDINGS FROM THE AUDIT
================================================================================

2.1 I2C PULL-UPS PROBABLY TOO WEAK FOR 400 kHz  (recommend changing)
    R30/R31 (kicker) and R32/R33 (expansion) are 4.7k.
    I2C Fast Mode allows 300 ns rise time. 4.7k into only 100 pF already gives
    roughly 400 ns, and these buses leave the board on cable, so real bus
    capacitance will be higher.
      -> Change R30-R33 to 2.2k (or 1.5k if the cables are long).
    Leave alone:
      - R16/R17 (IMU, 4.7k) - on-board, short trace, fine.
      - R34/R35 (OLED, 3k)  - matches the design doc's "~3 kOhm" exactly.

2.2 CONFIRM WHICH I2C INSTANCE PF0/PF1 BINDS TO  (firmware check)
    The CubeMX config enables FOUR I2C instances: I2C1, I2C2, I2C4, I2C5, and
    the board has exactly four independent I2C buses:
        OLED       PB8/PB9    -> I2C1
        KICKER     PB10/PB11  -> I2C2
        EXPANSION  PF14/PF15  -> I2C4
        IMU        PF0/PF1    -> I2C5 (by elimination)
    PF0/PF1 are the classic I2C2 pins on most STM32H7 parts. Confirm in the
    H723 datasheet / CubeMX that they can be driven as I2C5. If they cannot,
    the IMU and the kicker contend for I2C2 and one of them must move pins -
    which changes the netlist, so settle this BEFORE layout.

2.3 SUSTAINED 3V3 OVERVOLTAGE IS NOT PROTECTED  (accepted limitation)
    D10 (SMAJ4.0CA) does not conduct until 4.44 V, while the STM32 VDD abs max
    is 4.0 V. It is transient/ESD protection only. The polyfuse trips on
    overcurrent, not overvoltage. A powerboard regulator failure that puts 5 V
    on the 3V3 pin will kill the MCU.
    Upgrade path if this matters: replace F3/Q2 with an active OVP load switch
    (TPS2595 or NCP360). The 5 V rail is fine - D9 is a TVS0500 flat clamp at
    6.0 V, chosen to protect the TPS2116's 6.0 V abs max.

2.4 USB-ONLY OPERATION IS BENCH-PROGRAMMING ONLY  (documented on sheet 1)
    U3 (TLV1117-33) is an 800 mA LDO dissipating (5.0-3.3) x I.
    Doc load budget on 3V3 is ~1000 mA (150 mA STM32 + 650 mA radio + 200 mA
    SD). That exceeds both the LDO and a default USB port. Run from the
    powerboard for full-system operation. This is noted on the schematic.

2.5 RADIO POWER PIN COUNT
    J14 carries 650 mA on a single +3V3 pin (pin 1), returning on two grounds
    (pins 2 and 10). Within a header's rating but marginal. If the mezzanine
    part chosen in 1.2 has spare ways, give +3V3 a second pin.

2.6 MINOR / NICE TO HAVE
    - D2 (3V3 indicator) runs ~1.5 mA through R6=1k. Visible but dim.
      470R would give ~3 mA. D1 on 5V is ~3 mA already.
    - SW4/SW5/SW6 Value fields say USER_BTN0/1/2. The doc specifies PTS820;
      put the MPN in the BOM fields.
    - Consider a 10-22uF bulk cap local to the APA102 string on 06_LEDs. The
      string switches ~300 mA; C3 (22uF) is over on the power sheet.
    - Motor SPI is a 5-drop shared bus at 15.625 Mbit/s. R41/R42 (22R at the
      source) are in place, but treat stub length as a layout constraint.
    - Expansion and kicker headers supply +5V while their I2C pull-ups go to
      +3V3. Fine for open-drain devices, but if an attached board has its own
      pull-ups to 5V, that 5V lands on PF14/PF15/PB10/PB11 - confirm those are
      FT (5V tolerant) pins on the H723 before shipping cables.

================================================================================
4. HOW THIS SCHEMATIC IS MAINTAINED
================================================================================
All schematic edits go through the konnect MCP server - do not hand-edit the
.kicad_sch files. KiCad must be closed while konnect writes, or it refuses with
"stale_target".

Every change is verified by diffing the generated netlist against the previous
one by NET MEMBERSHIP (not by text), because ERC does not catch shorts created
by junctions auto-inserted at wire crossings. That check has caught two real
shorts and one scope regression (VBUS silently downgraded from a global power
symbol to a sheet-local label, which cut it off from the USB sheet).
