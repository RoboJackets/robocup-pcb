# Audit 2026-10-13: ControlBoard2027 and RadioBoard2027

Audit of both boards as ordered (PCB commit `79d0015`, 2026-10-11; schematics last changed in
`61fa0d1`, 2026-10-04). It was done to write the firmware specs ([ControlBoard2027_SPEC.md](ControlBoard2027_SPEC.md),
[RadioBoard2027_SPEC.md](RadioBoard2027_SPEC.md)), with the schematics as ground truth.

## Method

| Check | How | Result |
|---|---|---|
| Netlist, BOM | `kicad-cli sch export netlist / bom` on both root schematics | Used as ground truth for the specs |
| ERC | `kicad-cli sch erc --severity-all` | Control: 1 error (U2 VCAP 71/106 power-output tie; intended, **not** excluded in the project). Radio: 0 |
| DRC + schematic parity | `kicad-cli pcb drc --schematic-parity --refill-zones` on the saved boards (not re-saved) | Control: 0 errors, 0 unconnected, 0 parity, 2 warnings (J13 silk outline clipped by R34 pads). Radio: 0 / 0 / 0 / 0 |
| Layout facts | Scripts over the `.kicad_pcb` files (outline, stackup, positions, per-net widths, lengths, vias) | Used for the findings below |
| Schematic vs datasheets | Three independent reviewers (control power/USB/connectors; control MCU/peripherals; radio board and the J9/J2 link), pin by pin | No Critical findings |
| Documentation drift | Independent reviewer: DESIGN_NOTES, TODO, planning docs, CubeMX V0.3, sheet notes and Descriptions vs the netlist and PCB | About 60 stale or contradicting statements |
| BOM | Independent reviewer: datasheet links (HTTP), MPN vs footprint vs Vendor PN, ratings vs rails, ordering CSVs vs schematic | No wrong or missing parts |

Every finding below was checked against the files before it was accepted. "Verified" means it
was reproduced from the netlist, PCB file or datasheet during this audit.

## Not checked
- st.com and mouser.com were unreachable from this network: the STM32H723, LSM6DSV320X and USBLC6
  datasheet links, and lifecycle/stock for U2, U11 and the ESP32-C5 module.
- AN2606, AN5419 and RM0468 could not be downloaded; bootloader pin behaviour was checked only
  against DS13313.
- No powerboard or I2C kicker design exists in the repo to mate J15 and J10 against.
- Stock levels (the 2026-10-04 figures in DESIGN_NOTES are dated).
- Schematic readability (text overlap) was not rendered and inspected.

## 1. Design findings, ControlBoard2027

### Major

| ID | Finding | Evidence | Suggested fix |
|---|---|---|---|
| CB-1 | **A shunt fitted along a column joins two supplies.** J14 1-3 ties +5V_PB to VBUS (back-feeds the USB host); J16 3-5 does the same; J16 1-3 bypasses U8's reverse blocking; J17 1-3 and J18 3-5 drive the powerboard 3.3 V into the U7 LDO output. Only the silkscreen ("SHUNT ACROSS") prevents it. | Verified, netlist J14/J16/J17/J18 | Next revision: pin out so no adjacent pair joins two sources (for example the load on the centre pin of 1x3 headers), or use keyed/solder jumpers |
| CB-2 | **Mux switchover thresholds are far below the rails.** U9 (+3V3) moves to USB only when the powerboard 3.3 V falls to ≈ 2.34 V and back at ≈ 2.57 V; U8 (+5V) at ≈ 3.55 / 3.88 V. The radio needs ≥ 3.0 V and VDD33USB needs ≥ 3.0 V. When the powerboard ramps up while USB is attached, the TPS2116 breaks before making and waits for VOUT to fall to VIN1, so +3V3 dips to ≈ 2.6 V (and +5V to ≈ 3.9 V). Bench-only (on the robot there is no USB). | Verified: thresholds computed from R36-R43 and VREF 1.00 V; TPS2116 SLVSFG1A §7.6.1 | Raise the 3V3 threshold to ≈ 3.0 V (R39 ≈ 47-50k, re-compute R41) and the 5V rising point to ≥ 4.5 V; set a BOR level; firmware re-initialises the radio after PWR_SRC changes |
| CB-3 | **No overvoltage or reverse protection on the 3.3 V input.** D4 (TVS0500) breaks down at 7.5-8.4 V; the STM32 VDD abs max is 4.0 V. A 5 V-on-3.3 V cable fault reaches the MCU, SD card, IMU and radio. J15 puts +5V (pin 2) next to +3V3 (pin 3). | Verified, DS13313 Table 9, TVS0500 datasheet | Powerboard must regulate and the cable must be correct; next revision: 3.3 V-class TVS or OV switch, GND pin between the rails |
| CB-4 | **Motor connectors J4-J8 do not mate with the existing motor module.** Motor-module J2 is 8-pin (1 +5V, 2 GND, 3 +3.3V, 4 GND, 5 SCK, 6 MOSI, 7 MISO, 8 CS); this board is 6-pin (GND, SCK, GND, MOSI, MISO, CS). The J4 Description says the opposite ("matches drive-motorboard/motor-module J2"). | Verified by the reviewer from the motor-module netlist; J4 Description in the netlist | Change the motor module to the 6-pin pinout or build adapter cables; correct the J4 Description |
| CB-5 | **R16 (motor MOSI 30 Ω) is ~10 mm from PA7 and MOTOR_SPI_MISO runs between its pads.** Breaks the sheet note (within 5 mm) and CLAUDE.md §5/§8. R16 is the only 0805 series resistor. | Verified, R16 at (31, 38.5) 0805; DESIGN_NOTES m25 | Next layout: 0402 next to PA7, MISO routed around it |
| CB-6 | **DotStar footprint orientation is not confirmed (C1).** Footprint follows the BB-2020BGR-TRB drawing read as a top view; the drawing does not say. If it is a bottom view, CI/CO and DI/DO swap (VCC/GND do not), so the chain would not work but nothing is damaged. | Reviewer, footprint vs maker drawing | Check a sample on the first assembled board before populating more |

### Minor

| ID | Finding |
|---|---|
| CB-7 | USB attach inrush: VBUS sees only 8.9 µF directly, but U7 (no soft start) charges ≈ 85 µF on +3V3 and U8 charges the +5V caps from VBUS. Bench use only. |
| CB-8 | U7 AP7361C can dissipate (5.25 - 3.3) V x 0.75 A ≈ 1.5 W at F1's hold current, above what a SOT-223 sheds; USB-only operation with radio TX is not qualified. |
| CB-9 | D3 sits after Q1, so a large surge on +5V_RAW passes through the AO3401A (27 A pulsed rating) before it is clamped. |
| CB-10 | No ESD protection on J15 UART pins, J11/J12 pin 1, J3 SWD, USB CC1/CC2. |
| CB-11 | +5V budget: two expansion ports plus five DotStars can exceed F5's 0.95 A hold at 50 °C; relies on the firmware LED cap and the 0.55 A combined expansion allocation. |
| CB-12 | Button debounce RC (1 ms press / 2 ms release) is shorter than the switch's bounce spec (up to 10 ms); firmware debounce is required. |
| CB-13 | PA4 (ROM bootloader SPI1 NSS) floats in DFU; low risk. A 10k pull-up would remove it. |
| CB-14 | C24/C26 (VDDA/VREF+ 1 µF) are 6-10 mm from pins 32/33; R6 (SD CLK 30 Ω) is 5.8 mm from PC12. |
| CB-15 | 100 nF decoupling caps are drawn at different U2 pins on the schematic than where they sit on the board (DESIGN_NOTES m26). Electrically equivalent. |
| CB-16 | VCAP ERC error is not excluded in the project, although DESIGN_NOTES m21 and TODO 1.8 say it is. |
| CB-17 | SD lines DAT2/DAT3 have two vias each; counting 1.6 mm per via (as done for the radio SPI) they are ≈ 48.3 mm against CMD 44.45 mm, not "within 0.7 mm". No GND region on In2 under the SD B.Cu hops. Fine at 24 MHz, but the documented match was optimistic. |
| CB-18 | TP1 adds a stub on the card-side SD clock. |
| CB-19 | USB, SWD and RESET/BOOT0 are on three different edges (CLAUDE.md §2 asks for one accessible edge). |
| CB-20 | X1 ABM8 is rated -20 to +70 °C; gm margin is 1.8x (0.83 vs 1.5 mA/V). |

### Info
- The VBUS divider gives 2.96 V at 5 V: GPIO detection only, not the OTG VBUS comparator (as designed).
- ROM bootloader pins: PB10/PB11 (USART3) carry the kicker I2C; pre-V9.3 bootloaders drive TX push-pull there.
- The CTS 209-6MS ships with all switches ON (every ID bit reads 0).
- C38 (22 µF 6.3 V 0603) keeps only a fraction of its capacitance at 3.3 V.

## 2. Design findings, RadioBoard2027

### Major

| ID | Finding | Evidence | Suggested fix |
|---|---|---|---|
| RB-1 | **The radio hangs off the control board on J2 alone.** About 45.7 mm of the 54 mm board overhangs the control board's east edge with no standoff; USB-C, the buttons and the antenna cable are on the overhanging part, so every plug-in, button press or impact levers the 0.5 mm SMD joints of J2 and J9. | Verified, board positions | Radio H3 lands on the control board at (94.65, 11.15) board-relative with no part there: an M2 hole plus 5 mm standoff on the control board would carry it (check routing under it). Radio H4 lands on the microSD socket. Until then, strap or bracket the radio |
| RB-2 | **Same mux thresholds as CB-2.** U3 switches to USB only below ≈ 2.34 V on +3V3_HOST, below the module's 3.0 V minimum; plugging the control board in while on USB dips the module supply (break-before-make). | Verified, SLVSFG1A §7.6.1 | Raise the threshold (R12) in the next revision |

### Minor

| ID | Finding |
|---|---|
| RB-3 | D4 (TVS0500, 7.5 V breakdown) and D2 do not protect the 3.6 V module or the AP7361C (6.5 V abs max) against sustained overvoltage; ESD/surge only. |
| RB-4 | No radio-side pull-up on ESP_SPI_CS: unmated on the bench CS floats; with the control board off, R29 pulls CS low through the dead rail. Firmware should gate the SPI slave on PWR_SRC_HOST (GPIO9). |
| RB-5 | USB-C shield is floating; tie to GND (directly or 1 MΩ ∥ 4.7 nF). |
| RB-6 | No ESD on CC1/CC2. |
| RB-7 | USB attach inrush ≈ 60 µF behind an LDO with no soft start. |
| RB-8 | The radio overhangs ≈ 5.5 mm of the control board's microSD card entry, 5 mm above it. |
| RB-9 | Antenna: FXP831 peak gain 5.5-7.2 dBi at 5 GHz exceeds the module's certified ≤ 3.65 dBi (DESIGN_NOTES C1). Cap 5 GHz TX power, use 2.4 GHz, or change antenna. |
| RB-10 | Board file has no stackup section; the JLC04161H-7628 stackup exists only in the notes. |
| RB-11 | 02_ESP32 sheet: U1, C1, C2, R4, ANT1 sit outside every dashed box; sheets are A3 with A4 content. |
| RB-12 | No GND test point near TX/RX; no test points on +3V3_HOST/+3V3. |

### Info
- GPIO2/3/7 are strapping pins but none sets the boot mode; GPIO7 only matters if the JTAG-select eFuse is burned.
- ESP-Hosted defaults for the C5 are CLK = GPIO3, HANDSHAKE = GPIO1; the board uses the FSPI IO_MUX pins (CLK 6, MOSI 7, MISO 2, CS 10) and HANDSHAKE 3, which must be set in menuconfig.
- Back-feed, radio on USB with the control board off: PB3-PB7 and PE1 are FT pins, so no damage and no powering of the STM32.
- J2 ↔ J9 mating verified on all 20 pins plus shield (row swap per the Samtec mated drawing).

No wrong, mis-packaged or under-rated part, no mismatched Vendor PN, no missing line. The
ordering CSVs (2026-10-04) match today's schematic in refs, quantities, MPNs, Vendor PNs,
footprints and ratings.
